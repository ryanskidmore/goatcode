# Bug Report: Subagent tasks can stall on provider quota exhaustion without effective fallback

## Summary

Delegated subagent tasks (especially background `task` executions) could appear to hang/retry indefinitely when the selected model/provider was quota-exhausted. The system surfaced `session.error`, but background execution did not actively switch to a fallback model/provider and restart the task. This produced repeated failures and poor recovery behavior.

## User-visible symptoms

- Background delegated task remains `running` or repeatedly fails without useful progress.
- `background_output` polling shows no completion despite repeated checks.
- In quota-exhausted periods, subagent launches keep targeting the same unavailable model/provider.

## Root cause

1. **No active runtime retry path in background task manager**
   - `BackgroundAgentManager.handleSessionError` previously failed the task directly (or salvaged assistant output), but did not trigger fallback relaunch behavior.

2. **Existing fallback hooks were not wired into background execution recovery**
   - Hooks like `foreground-fallback` can annotate event properties (`retryRequested`, `retryWithModel`), but background manager was not consuming this metadata to relaunch tasks.

3. **No hard stop / bounded retry policy for provider/model recovery in manager**
   - There was no explicit manager-owned retry budget for model/provider switching, risking repeated ineffective attempts.

## Fix design

### 1) Background manager now classifies provider/model failures

Added robust classification logic in `src/features/background-agent/manager.ts` for:

- `quota`
- `rate-limit`
- `service-unavailable`
- `model-unavailable`

Signals include status code and common provider phrases (e.g., `insufficient quota`, `quota exceeded`, `usage limit`, `resource exhausted`, `too many requests`, `service unavailable`, `model not found`).

### 2) Event hook forwards richer session.error metadata

`src/features/background-agent/event-hook.ts` now passes metadata into manager:

- raw `error`
- `model`
- `retryRequested`
- `retryWithModel`

This lets manager consume fallback hints generated by hooks, while still operating safely when hints are absent.

### 3) Manager-owned fallback relaunch path

On classified provider/model failure, manager now:

1. Builds candidate fallback models from task fallback chain.
2. Merges hook-suggested model (`retryWithModel`) if present.
3. For **quota** failures, prioritizes switching to a **different provider** first.
4. Skips previously attempted models.
5. Cleans up old session state and deletes stale child session.
6. Releases old concurrency slot safely.
7. Relaunches same task with next model and increments retry count.

### 4) Safe loop termination

Introduced hard cap `MAX_MODEL_SWITCH_RETRIES = 4` in manager.

- If retry budget is exhausted, task fails with explicit reason.
- If no eligible fallback model remains, task fails immediately with clear message.

### 5) Sync session tracking enriched for recovery

`task` sync path now registers extra context into manager tracking:

- original prompt
- parent session id
- description/title
- fallback chain

This enables model/provider recovery behavior to work consistently for sync/background tracked sessions.

## Code changes

- `src/features/background-agent/manager.ts`
  - Added provider failure classification helpers.
  - Added fallback relaunch logic with retry budget and attempted-model tracking.
  - Added safe concurrency release helper to avoid mismatched pool release after model switch.
  - Extended `trackSyncSession` to carry prompt/fallback metadata.

- `src/features/background-agent/types.ts`
  - Extended `BackgroundTask` with runtime retry state:
    - `title`, `fallbackChain`, `retryCount`, `attemptedModels`, `concurrencyPoolKey`

- `src/features/background-agent/event-hook.ts`
  - Forward session.error metadata into manager for recovery decisions.

- `src/tools/delegate-task/executor.ts`
  - Pass sync tracking metadata (`prompt`, `parentSessionID`, `title`, `fallbackChain`) to manager.

- `src/features/background-agent/manager.test.ts`
  - Added tests covering:
    - provider-switch fallback on quota exhaustion
    - fail-fast when no fallback candidates remain

- `src/tools/delegate-task/category-resolver.ts`
  - Preserves delegate-task fallback chains while applying `goatcode.config.ts` category overrides.
  - Supports category-level `fallback_models` + `fallback_mode` merge semantics (`replace` / `append` / `prepend`).

- `src/plugin/compositor.ts`
  - Uses shared fallback merge logic for agent-level `fallback_models` + `fallback_mode` so config behavior is consistent.

- `src/agents/fallback-chains.ts`
  - Added `mergeFallbackChains(...)` helper and tests for replace/append/prepend semantics.

- `src/shared/data-path.ts`
  - Cache root standardized to `~/.cache/opencode` (with legacy helper retained for migration).

- `src/shared/connected-providers-cache.ts`
  - Migrates legacy cache files from `~/.cache/goatcode-sh` to `~/.cache/opencode` when present.

- `src/tools/background-task/output/handler.ts`
  - Enriches failed task output with fallback diagnostics (retry count, attempted models, configured fallback chain).

## Residual risks / follow-ups

1. **Provider health awareness**
   - Current selection is fallback-chain + connected providers + attempted models.
   - Could be improved with short-lived provider/model circuit-breaker state to avoid retrying known-degraded providers across tasks.

2. **Telemetry**
   - Add explicit counters/metrics for fallback attempts, exhausted retries, and provider-switch success rate.

3. **Cross-process persistence**
   - Retry attempt state is task-local in-memory; this is acceptable for current task lifecycle but not persisted across process restarts.
